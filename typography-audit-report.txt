1. EXECUTIVE SUMMARY
============================================================

Overall Typography Quality:
The codebase utilizes a clean, modern sans-serif typography foundation based on Google Fonts' "Plus Jakarta Sans". The overall visual hierarchy is bold and legible, leveraging dynamic CSS clamp() fluid typography for section headings and hero headers. However, typography drift exists due to numerous inline font-size overrides scattered across individual HTML page files, as well as unused font imports in the admin stylesheet.

Typography System:
- Primary Font: "Plus Jakarta Sans" (sans-serif)
- Fallback Stack: system-ui, -apple-system, Segoe UI, Roboto, sans-serif
- Design System Architecture: CSS Custom Properties in :root (--font, --font-serif) and global CSS utility classes.
- Theme System: Dark Obsidian and Light Theme system in admin dashboard using CSS custom property overrides.

Responsive Typography:
Heading sizes leverage CSS clamp() functions (vw-based fluid scaling), allowing smooth scaling between mobile and desktop viewports without abrupt breakpoint steps. Navigation typography adapts via CSS media queries at <=900px and <=560px.

Accessibility Risk:
Low to Medium. Color contrast for primary typography (--teal-900: #0d1f3c on #f8f5f0 cream background) is strong. However, micro-text instances (9.5px on brand small, 10.5px on sticky call small) fall below the 12px recommended legibility threshold.

Consistency:
Moderate. While global.css sets a standard scale, multiple HTML files (the-woodlands-tx-insulation.html, spring-tx-insulation.html, spray-foam-insulation.html, index.html) hardcode arbitrary inline font sizes (e.g. style="font-size: 1.25rem", style="font-size: 1.5rem"). Additionally, admin.css imports JetBrains Mono via Google Fonts URL but never references it in any CSS selector.

Key Findings:
1. Unused Web Font Import: JetBrains Mono is imported in admin.css via Google Fonts URL but is never declared in any CSS rule, resulting in unnecessary network requests.
2. Inline Typography Drift: Multiple location HTML pages override heading and table sizes via inline style attributes instead of using global CSS utility classes.
3. Sub-12px Font Sizes: Micro-typography elements (9.5px and 10.5px) reduce legibility on high-DPI and mobile screens.

13. ACCESSIBILITY
============================================================

- Minimum Readable Text Size:
  Elements with sub-12px text sizes violate the recommended 12px minimum for web readability:
  * brand small (9.5px in assets/global.css:67)
  * sticky-call small (10.5px in assets/global.css:372)
  * sidebar-badge (10px in admin/admin.css:153)
  * nav-counter (11px in admin/admin.css:233)
  * prose-faq-label (11px in assets/global.css:748)

- Color Contrast:
  * Body text (--ink: #2b2d42) on body background (--cream: #f8f5f0) provides a high contrast ratio of ~11.8:1 (exceeds WCAG AAA requirement of 7:1).
  * Dark cards (--teal-900: #0d1f3c) with white text (#ffffff) provide a contrast ratio of ~15.9:1.
  * Muted text (--muted: #6c757d) on small 11px/12px labels should be audited on custom backgrounds.

- Focus & Interactive States:
  Buttons and links include focus outline/border-color updates (e.g. input:focus { border-color: var(--accent); }).

- Zoom & Text Scaling:
  Because base font sizes rely on px and rem units, standard browser zoom (100% to 200%) scales typography predictably.

14. SEMANTIC HEADING STRUCTURE
============================================================

Semantic Heading Hierarchy Audit:
- All main pages correctly feature a single <h1> element inside the hero section (.hero-copy h1 or .location-hero-copy h1).
- Main page sections use <h2> elements for primary titles (.section-heading h2, .section-copy h2).
- Cards and sub-components use <h3> elements (.svc-card strong, .service-overlay h3, .benefit-grid h3).

Semantic Deviations & Issues Identified:
1. Division-based Headings:
   In assets/global.css line 166, .request-heading .request-title is styled as a 20px heading alongside h2. On pages where a <div> or <span> is used with class .request-title instead of an <h2>, screen readers will not register the heading level.
2. Inconsistent FAQ Heading Elements:
   Global FAQ sections use <button><strong>...</strong></button> inside <article> for accordion questions, while spring-tx-insulation.html lines 458-468 uses <h2> style="font-size: 1.5rem;" for FAQ questions.
3. Card Component Tagging:
   In assets/global.css line 119, .svc-card strong is used as the primary card title (styled as 17px bold header) rather than an <h3> element, omitting it from the document outline.

[HIGH]
ID: TYPO-01
Title: Unused Web Font Import in Admin Stylesheet
File: admin/admin.css
Line: 2
Component: Admin Theme (@import)
Code:
  @import url('https://fonts.googleapis.com/css2?family=Plus+Jakarta+Sans:wght@400;500;600;700;800&family=JetBrains+Mono:wght@400;500;600&display=swap');

[HIGH]

Title: Inline Typography Overrides Bypassing Design System
File: the-woodlands-tx-insulation.html, spring-tx-insulation.html, spray-foam-insulation.html, index.html

Impact:
  Creates typography drift and inconsistent heading scaling across location pages.
Recommendation:
  Remove inline style="font-size: ..." attributes and replace with standard CSS classes.

[MEDIUM]
